### window
全局变量
引入的 第三方库、自己写的js代码，都可以向其中写入东西
写入的东西可以被该页面使用的所有js使用

在JavaScript的全局空间里，一个名字只能存一个值，
如果两个文件写入了同一个名字，后面写入的就会覆盖前面写入的
（全局污染）（变量遮蔽）<span id = "全局污染">

ai对全局污染同样很难处理

---

在首行引入`animejs`库后（`anime.js`），因为浏览器按前后顺序读取html文件，在浏览器加载完之后，向window全局变量中挂入变量`anime`
写入之后，页面里的任意js代码都能调用这个变量

## （传统前端）问题 ：
1. 这样，由于没有明确写代码引入，全靠顺序，由人来管理，依赖关系就很难确定
2. （全局变量）同一个页面引入了两个变量名，重名就会导致[全局污染](#全局污染)
    项目一旦长大，重名的事就是非常令人头疼

## 工程化 - 模块化
解决上面的问题

### export / import
也被叫做ES模块（ES6时候引入ES Modules，即export/import）

每个js写的东西，默认只有自己可以看见，
若想共享给别的js使用，要标export
用别的js的东西，要标import

`import{a, b} from lib_xx`
`export function func_xx(){abcd...}`

### ES
ES ≈ JS
ES = ECMAScript，是一份规范文档 / js是按照es规范实现的编程语言
ES6 : ES第六版（2015）

阅读4_1的[readme](../frontend/README.md)，

### 模块化后产生的新问题，新发现的问题
下方[vite](#vite)解决
1. 不能双击打开html了
2. 请求变多，页面变慢
    （f12可以看到，每个css和js都发起网络请求(排队)、
    部分文件请求响应时间长）
3. 改了，刷新却不变（浏览器缓存，同名文件使用本地缓存，不再请求）
    - 看起来，ai难以识别这种缓存问题
    - 在以前，会在文件名后面加时间戳来避免这个问题，
    `layout.css --> layout_20261125.css`
    - 一般在引用时，加上一串参数

#### 初始化npm
`npm init -y`
产生 `package.json` 、 `package-lock.json`<span id = "package-lock.json"> 、 `node_modules`<span id = "node_modules">

__本项目npm init 在`./frontend`中，后续所有命令都cd到这个路径后执行__

##### package.json
(package.json 可以手动删改)
该项目的npm档案，记录该项目中npm装了哪些东西，项目可以跑哪些命令
内部键值对 可用于发布npm包
(（弹幕）相当于`python`项目的`pyproject.toml`)

可只留
```json
{
  "name": "frontend",
  "version": "1.0.0",
    "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  }
}
```

其中，scripts可将长的命令，登记成简短的命令
```json
{
  "xxxx" : "xxxx",

  "scripts" :{
    "dev" : "vite",
    "build" : "vite build",
    "preview" : "vite preview"
  }
}
```

##### npm run
之后，就可以执行
`npm run dev`
`npm run build`
`npm run preview`
npm run xxxx
xxxx（键）对应的命令（值），写在package.json里

npm run先在`./node_modules/.bin`里寻找命令；若其中无，
再在系统命令中找
（弹幕：类alias）

下面的`.bin`文件夹装 [可执行命令](./1_终端命令.md#linux文件夹)
用Vite时，用的就是`.bin`里的这个

#### vite使用

##### 预览
1. 在[初始化npm`npm init`](#初始化npm)的目录下，执行`npx vite`
2. 或者 [初始化npm`npm init`](#初始化npm)的目录下 执行 ` .\node_modules\.bin\vite`

ps，本款在项目根目录未执行`npm init`，而在`./frontend`执行
在`项目根目录下`执行上述任何操作，都会因为路径问题失败
所以 项目根目录下 无法启用vite，都需要切到`./frontend`中执行

##### 构建/打包/build
`npx vite build`
 ` .\node_modules\.bin\vite build`

 生成`dist`文件夹，将css和js文件，各自合成为一个
 （生成的文件是被压缩过的，压缩为一行，专供浏览器使用）
 生成的css和js文件存在`./dist/assets`里，其命名的哈希码用于解决 `浏览器缓存问题`

 但这个命令只认`index.html`一个入口，若要打包多个入口，要改配置

 但此处略
 因为用`React`实现更方便，React会把两个html打包为一个

 ##### 查看build产物
 `npx vite preview`
 起本地服务器，提供`dist`文件夹的资源
 真正上线时候也是上线`dist`文件夹内的资源
 `dist`文件夹内的资源是被压缩过的，机器用的，不是给人用的

 __让ai生成源代码，即多个html，多个css，多个js这种__
 __然后使用 构建/ 打包/ build 功能生成机器用代码（dist）__
 __只修改源代码__
 __不要修改`dist`内的代码，重新build生成即可__
